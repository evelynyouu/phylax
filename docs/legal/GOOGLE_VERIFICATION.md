# Google OAuth checklist for Phylax

Phylax uses one Google Cloud project and one OAuth client for two things (README.md step 2.3):

1. **Sign in with Google**, run by Supabase Auth. Scopes: `openid`, `userinfo.email`, `userinfo.profile` ([Supabase Google guide](https://supabase.com/docs/guides/auth/social-login/auth-google)).
2. **Connect Gmail**, run by Phylax itself (`lib/gmail.ts:10-11`). Scopes: `https://www.googleapis.com/auth/gmail.readonly`, `openid`, `email`, requested with `access_type: "offline"` and `prompt: "consent"` (`lib/gmail.ts:28-36`).

Google lists `gmail.readonly` as a **restricted** scope ([Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes)). Workspace policy defines restricted Gmail scopes as any scope that lets an app "read, create, or modify message bodies (including attachments), metadata, or headers" ([Workspace policy](https://developers.google.com/workspace/workspace-api-user-data-developer-policy)).

Status key: **Done** = the code or repo already does this. **To do** = not done. **Check** = depends on console settings the code cannot show.

## Part A. Consent screen setup while the app is in Testing

Testing is the right mode for a student demo. Google says: "if your app is in the development, testing, or staging phases, verification isn't required", the app "is only available to users you add to the list of test users", and "a user cap is in effect, and the refresh token lifetime is limited" ([Restricted scope verification](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)).

## Part B. Public launch (anyone with a Google account)

Google: "We recommend that you only submit your app for verification if you want to make your app available to any user with a Google Account" ([source](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification)). Without verification, Google shows the unverified app screen and caps new users; failing to verify can lead to "Google sign-in being disabled for your users" ([Verification FAQ](https://support.google.com/cloud/answer/13463817)).

### Simplest compliant path for a resume project

Keep the Google app in **Testing**, list your testers, put the privacy policy and in-app disclosure live anyway, and label the public site as a demo that uses sample data (`npm run demo` mode) for everyone else. Note that demo mode is disabled when `NODE_ENV` is `production` (`lib/session.ts:5-7`), so a public sample-data deployment needs a code change.
